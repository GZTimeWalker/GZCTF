# GZCTF 技能树与共享类别重构设计

- 日期：2026-09-21
- 状态：已完成设计确认，等待书面规范审阅
- 目标分支：`develop`
- 设计范围：将现有学习路线和模块重构为技能树与全局共享类别

## 1. 执行摘要

现有管理端使用 `LearningPath → LearningModule → ModuleItem`，管理员需要直接编辑 Modules JSON。这种结构把类别复制在每条路线的修订中，不适合多个技能树共享同一类别及同一组题目。

本次重构将学习结构调整为：

```text
技能树 ←多对多→ 全局类别 ←多对多→ 题目或课节
```

技能树负责学习主题、类别选择和类别排序；全局类别负责共享题目、课节和内容顺序。管理员创建或发布题目和课节时选择类别，技能树编辑页不再直接填写内容项或 JSON。

## 2. 产品术语

| 原术语 | 新术语 | 说明 |
|---|---|---|
| 学习路线 / Learning Path | 技能树 / Skill Tree | 学员选择的学习方向 |
| 技能模块 / Learning Module | 全局类别 / Skill Category | 可被多棵技能树共享的内容集合 |
| ModuleItem | CategoryContent | 类别对题目或课节的有序引用 |
| 当前学习路线 | 当前技能树 | 学员主要学习方向 |

导航、页面标题、个人中心和管理员后台统一使用“技能树”和“类别”，不再向用户展示“路线”和“模块”。

## 3. 已确认的产品规则

### 3.1 技能树

- 技能树包含名称、简介和系统预设 CTF 图标。
- 名称和简介不区分中文与英文，所有界面显示同一份内容。
- 图标只能从系统预设列表中选择，首版包括 🚩、🕸️、🔐、💣、🧠、🤖 等适合 CTF 的图标。
- 技能树使用系统生成的唯一 ID，不要求管理员填写 slug。
- 空技能树可以保存、发布和展示。
- 空技能树详情页显示“内容建设中”的空状态。
- 学员可以加入多棵技能树，并设置一棵当前技能树。

### 3.2 全局类别

- 类别包含名称、简介和系统预设图标。
- 类别是独立的全局实体，可以同时属于多棵技能树。
- 类别允许暂时不属于任何技能树，便于管理员提前整理和合并。
- 同一类别在所有技能树中共享题目、课节和内容顺序。
- 在任意管理入口修改类别内容，所有引用该类别的技能树立即同步。
- 每棵技能树单独保存类别显示顺序，因此同一类别可在不同技能树中处于不同位置。

### 3.3 题目与课节

- 题目和 Markdown 图文课节继续独立保存，只保存一份。
- 同一道题或同一篇课节可以属于多个类别。
- 题目、课节、提示和 WP 继续维护中英文内容，并按现有规则回退到英语。
- 题目和课节都采用草稿、已发布、停用状态。
- 未分类草稿允许保存。
- 发布题目或课节时必须至少选择一个有效类别。
- 发布所选类别必须至少属于一棵未删除的技能树。
- 新发布内容加入类别时默认追加到类别末尾。
- 已发布内容允许继续修改所属类别，保存后立即生效。

## 4. 发布边界

### 4.1 技能树结构发布

- 技能树保留草稿和已发布修订机制。
- 修订只保存技能树引用的类别及类别显示顺序。
- 空类别列表是合法的发布内容。
- 修改已发布技能树的类别组成或顺序时，管理员编辑草稿并重新发布。
- 发布时通过行版本和数据库事务原子切换当前版本。
- 学员始终读取一个完整的已发布技能树结构。

### 4.2 类别内容实时同步

- 类别内部的题目、课节和内容顺序不进入技能树版本快照。
- 给类别新增或移除已发布内容后，无需重新发布技能树。
- 所有引用该类别的已发布技能树立即读取最新类别内容。
- 类别内容变化会立即改变相关技能树的题目数、课节数和进度分母。
- 用户已有题目和课节完成记录不变，个人中心按当前类别内容实时重算完成率。

## 5. 管理员交互

### 5.1 技能树列表与创建

管理员在 `/admin/skill-trees` 查看技能树列表和状态。创建表单包含：

- 名称。
- 简介。
- 系统预设 CTF 图标。

创建后进入技能树编辑页。管理端不再展示 Modules JSON、内容 UUID 或原始结构 JSON。

### 5.2 技能树编辑

技能树编辑页支持：

- 修改名称、简介和图标。
- 从全局类别库选择一个或多个类别。
- 直接创建新类别并加入当前技能树。
- 拖拽调整类别在当前技能树中的顺序。
- 从当前技能树移除类别，但不删除全局类别。
- 预览草稿。
- 发布草稿。

### 5.3 类别管理

管理员在 `/admin/skill-categories` 管理全局类别：

- 创建和编辑名称、简介、图标。
- 查看类别所属技能树。
- 查看类别中的题目和课节。
- 拖拽调整全局内容顺序。
- 将类别加入或移出技能树。
- 合并重复类别。
- 删除类别。

类别合并时管理员选择保留类别和待合并类别。服务端合并技能树引用和内容关联，重复关联只保留一次。保留类别原有内容排在前面，迁入内容按原顺序追加。

### 5.4 题目与课节发布

题目和课节编辑页提供可视化类别选择器。发布流程为：

1. 选择一棵技能树，用于筛选类别。
2. 勾选一个或多个类别。
3. 可继续选择其他技能树并勾选类别。
4. 如果所选技能树没有类别，弹窗要求输入类别名称、简介和图标并创建类别。
5. 服务端校验后发布内容并建立全局类别关联。

内容绑定的是全局类别。某个类别被多棵技能树引用时，内容自动出现在所有这些技能树中。

## 6. 学员体验

- 导航栏“学习”改为“技能树”，图标改为树状结构图标。
- 技能树列表地址为 `/skill-trees`。
- 技能树详情地址为 `/skill-trees/{id}`。
- 旧 `/learn` 及其子地址跳转到对应技能树地址。
- 技能树卡片展示图标、名称、简介、类别数、题目数和课节数。
- 技能树列表和详情页不展示个人聚合完成率。
- 技能树详情按类别展示题目和课节，允许自由进入任意内容。
- 个人中心展示技能树完成率、类别完成情况、题目和课节完成数、当前技能树和最近学习记录。
- 共享题目解出一次后，在所有引用它的类别和技能树中同步显示完成。

## 7. 数据模型

### 7.1 核心实体

| 实体 | 责任 | 关键约束 |
|---|---|---|
| `SkillTree` | 技能树稳定身份与基本信息 | 系统生成 ID；名称、简介、IconKey；软删除 |
| `SkillTreeRevision` | 草稿或已发布类别结构 | 每棵技能树最多一个草稿和一个当前发布版本 |
| `SkillTreeCategoryRef` | 修订对类别的有序引用 | `(RevisionId, CategoryId)` 唯一；`(RevisionId, SortOrder)` 索引 |
| `SkillCategory` | 全局共享类别 | 名称、简介、IconKey；软删除 |
| `CategoryContent` | 类别对题目或课节的有序引用 | 必须且只能引用一种内容；同类别同内容唯一 |
| `Challenge` | 靶场题 | 草稿、已发布、停用；可绑定多个类别 |
| `Lesson` | Markdown 课节 | 草稿、已发布、停用；可绑定多个类别 |
| `Enrollment` | 用户加入技能树 | `(UserId, SkillTreeId)` 唯一；每用户最多一个当前技能树 |
| `ChallengeProgress` | 全局题目完成记录 | `(UserId, ChallengeId)` 唯一 |
| `LessonProgress` | 全局课节完成记录 | `(UserId, LessonId)` 唯一 |

### 7.2 图标

数据库保存稳定的 `IconKey`，不直接保存任意 Emoji。前后端共享允许列表，API 拒绝未知值。这样可以调整显示图形而不修改历史数据。

### 7.3 历史快照

软删除技能树时保留名称、简介、图标、最后发布版本和加入记录，使个人中心可以继续显示历史记录。被删除技能树不会出现在发现页、搜索结果或当前技能树候选项中。

## 8. 删除与合并

### 8.1 技能树删除

- 删除前 API 返回类别数、题目数、课节数和加入学员数。
- 空草稿技能树使用普通确认。
- 有类别、内容、已发布版本或学员记录时，客户端要求输入完整技能树名称。
- 服务端重新验证确认名称和行版本。
- 删除采用软删除。
- 删除后立即从学员端和默认管理列表隐藏。
- 用户当前技能树指向该技能树时自动清除。
- 共享类别、题目、课节、加入记录和完成记录全部保留。

### 8.2 类别删除

- 被技能树、题目或课节引用的类别不能直接删除。
- 管理端展示影响统计并要求二次确认。
- 确认后软删除类别，移除草稿中的类别引用，并停止该类别的所有活动展示。
- 已发布修订中的类别引用和类别内容关联保留用于历史审计，读取当前技能树时过滤已删除类别。
- 题目、课节和用户完成记录保留。

### 8.3 类别合并

- 合并在单个数据库事务内完成。
- 技能树引用按 `(RevisionId, CategoryId)` 去重。
- 内容关联按类别和内容身份去重。
- 合并后重新生成连续的内容顺序。
- 待合并类别标记删除并记录保留类别 ID。
- 并发修改或行版本冲突时整体回滚。

## 9. API 边界

旧接口正式废弃：

- `/api/learning-paths`
- `/api/admin/learning-paths`
- 以 LearningPath 或 LearningModule 命名的前端生成类型

新接口按以下边界提供：

- `SkillTrees`：公开列表、详情与已发布结构。
- `Enrollments`：加入、退出和设置当前技能树。
- `AdminSkillTrees`：创建、草稿编辑、影响预览、发布和软删除。
- `AdminSkillCategories`：类别 CRUD、技能树关联、内容排序、合并和删除。
- `AdminChallenges`：题目草稿、类别选择和发布。
- `AdminLessons`：课节草稿、类别选择和发布。
- `MyLearning`：当前技能树、历史技能树和个人进度。

所有管理员写接口继续要求 `Admin` 权限。列表 DTO 不返回 Flag、令牌哈希、未发布正文或私人学员字段。

## 10. 数据迁移

### 10.1 当前 Learning 数据

- 每个 `LearningPath` 迁移为一个 `SkillTree`。
- 路线标题优先使用当前展示标题；简介使用当前展示简介。
- 系统为迁移技能树分配默认图标。
- 每个 `LearningModule` 迁移为独立 `SkillCategory`。
- 同名模块不自动合并。
- 每个 `ModuleItem` 迁移为 `CategoryContent`。
- 模块顺序迁移为 `SkillTreeCategoryRef.SortOrder`。
- 模块内内容顺序迁移为 `CategoryContent.SortOrder`。
- `Enrollment`、当前路线、课节完成和题目完成记录重新关联并保留。
- 保留旧 `LearningPath.Slug → SkillTree.Id` 重定向映射，使 `/learn/{slug}` 可以跳转到新技能树地址。

### 10.2 旧比赛与 ZIP 导入

- 每场旧比赛生成一棵草稿技能树。
- 每个旧题分类生成独立类别，不与现有同名类别自动合并。
- 导入题目绑定到对应类别。
- 旧题关键字段、附件哈希、Flag、容器配置和来源映射继续保持。
- 导入可重复执行，不重复创建技能树、类别或内容关联。

## 11. 缓存与性能

- 技能树列表使用投影查询，不加载类别内容实体图。
- 技能树详情按发布类别引用批量查询类别与内容，禁止逐类别 N+1。
- 为 `SkillTree(IsDeleted)`、`SkillTreeRevision(SkillTreeId, Status)`、`SkillTreeCategoryRef(RevisionId, SortOrder)`、`CategoryContent(CategoryId, SortOrder)` 建立索引。
- 技能树结构发布只失效该技能树缓存。
- 类别内容修改失效所有引用该类别的技能树缓存。
- 进度继续从全局题目和课节完成记录聚合，不重复存储技能树完成状态。

## 12. 错误处理

- 发布或删除发生行版本冲突时返回稳定冲突代码，客户端提示刷新。
- 技能树、类别或内容不存在、已删除或状态不允许时返回明确字段错误。
- 发布内容未选择类别时拒绝发布。
- 发布内容选择的类别不属于任何技能树时拒绝发布。
- 删除确认名称不匹配时不执行任何修改。
- 类别合并发生唯一约束或并发冲突时事务整体回滚。
- 迁移校验失败时记录失败批次，不发布部分技能树结构。

### 13.1 后端

- 技能树和类别字段、图标允许列表及关联唯一性测试。
- 空技能树发布测试。
- 技能树草稿发布和并发冲突测试。
- 共享类别内容跨技能树即时同步测试。
- 内容多类别关联与去重测试。
- 未分类草稿和发布分类校验测试。
- 空技能树发布内容时内联创建类别测试。
- 全局内容排序测试。
- 技能树软删除、当前指针清除和历史记录保留测试。
- 类别删除与类别合并事务测试。

- 旧数据库与 ZIP 导入回归测试。

### 13.2 前端

- 创建技能树只显示名称、简介和预设图标。
- 技能树编辑页无 JSON 输入框。
- 选择已有类别、新建类别和拖拽排序测试。
- 题目与课节发布弹窗的技能树筛选、多选类别和内联创建类别测试。

- `/learn` 到 `/skill-trees` 重定向测试。

- 空技能树空状态测试。
- 中英文界面不得显示原始翻译 key。

### 13.3 部署

- Dockerfile 入口继续为 `dotnet GZCTF.dll`。
- 应用端口继续为 8080，健康检查与指标继续为 3000。
- `GZCTF_` 环境变量、PostgreSQL、Redis、存储和容器提供器配置保持兼容。

## 14. 验收结果

本设计完成后应满足：

- 管理员无需填写 JSON 即可创建和发布技能树。
- 全局类别可被多棵技能树共享，题目、课节和顺序保持一致。
- 题目和课节在自身发布流程中选择类别。
- 空技能树允许发布，并能在后续发布内容时创建类别。
- 删除技能树或类别不会删除题目、课节和学习完成记录。
- 已有 Learning 数据和旧比赛导入数据能够无损迁移。
- 学员入口、地址和产品术语全部切换为技能树。
